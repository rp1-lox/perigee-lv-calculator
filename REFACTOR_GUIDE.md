## 0. Prime rules (violating any of these is a failed refactor)

1. **`src/` is the source of truth. NEVER edit `lv_calc.html`** — it is generated by `python build.py` and will be overwritten. Every change goes in `src/js/NNN-name.js`, `src/css/styles.css`, or `src/index.html`.
2. **The build gate must pass after EVERY change**: `python build.py` runs a U+FFFD corruption guard, `node --check` on the concatenated JS, and `tests/math.test.js` (**499 assertions** as of this writing). A failing gate means STOP and fix — never comment out a test, never ship around it. If Node isn't on PATH (fresh PowerShell): `$env:Path="C:\Program Files\nodejs;$env:Path"` first.
3. **Refactor = behavior-preserving.** If a change would alter any number, any rendered output, or any persisted format, it is not a refactor — write it down in REFACTOR_LOG.md as a proposal and do not do it.
4. **Never touch these (byte-behavior-frozen):**
   - `calculate()` and `evalAtPayload()` in `160-calculate.js` — the LV calculator core. Work around them (`calculateWithS15()` in 150 is the editable wrapper).
   - `destOnOrbitDV()` (145) — pure transcription of calculate()'s destination-ΔV logic, pinned by regression goldens.
   - `progNmComputeEdgeDv` (430) — the ONLY source of solved-maneuver ΔV magnitudes. The whole mission accounting's integrity ("ΔV parity") hangs on this.
   - The physics core numerics: `385-physics-core.js`, `386-physics-integrator.js` — you may MOVE code (see §4) but not change formulas, step ladders, tolerances, or iteration counts. Every meaningful number in them is pinned by a gate golden.
5. **Golden sanity numbers** (spot-check in the browser after any risky change):
   - Vehicles page, builtin Saturn V, 185×185 km @ 28.5° from lat 28.5 → **Est. Max Payload 150,838 kg**.
   - `devSeedApolloMission({force:true})` → LEO→TLC maneuver `dvRequired` **3143**, TLC→LLO **822**, `missionBudget(m).dvExpended` **13010**.
   - Gizmo on the TLC maneuver decomposes to **pro 3143.0 / rad ≈0 / nrm ≈0**.
6. **Encoding**: all file I/O in UTF-8. The build gate catches U+FFFD corruption — if it fires, you destroyed non-ASCII characters (this killed a previous delegate model repeatedly). PowerShell traps: `>` redirects write UTF-16 (use `cmd /c "... > file"`); `Out-File` needs `-Encoding utf8`.
7. **Do not commit `divergence/`** (unrelated local scratch). Do not create PRs; commit to `dev` with descriptive messages. Never update the existing v2.0.0 GitHub release.

## 1. What this thing is

An orbital mission planning tool ("Rocket Playground") that ships as ONE self-contained HTML file (GitHub Pages, embedded on perigeeaero.shop — so URL-based features are impossible and all assets must be inline). Source = 81 modules in `src/js/` (filename sort = load order) + `src/css/styles.css` + `src/index.html` skeleton, concatenated by `build.py`.

Two halves, increasingly integrated:
- **LV calculator** (roughly modules 010–270): stage/vehicle editing, Townsend launch performance math (`lvPerformance`/`lvMaxPayload` in 140), destinations, trade studies, spacecraft editor.
- **Mission planner** (roughly 300–590): a program/mission model where `m.log` (an ordered event list) is the source of truth and `missionRecompute(m)` REPLAYS the whole log to rebuild all runtime state. On top of that sits a real physics engine (JPL mean-element ephemeris, symplectic n-body propagation, differential-correction targeting) and a 3D-projected trajectory view.

## 3. Architecture invariants (these are LOAD-BEARING — the refactor must preserve them, and ideally make them more obvious)

- **Event model = re-simulated plan.** `m.log` is authoritative. Every mutation: edit `m.log` → `missionRecompute(m)` → `missionRenderDetail()`. Never mutate runtime vehicle state directly. The recompute tail hooks `autosaveScheduleSave()` and `missionUndoCapture()` — preserve them.
- **One maneuver event kind** (post-unification): `MNODE {at:{kind:'met',value_s}, dvPro_ms/dvRad_ms/dvNrm_ms, mode:'solved'|'manual', target?:{fromNode,toNode}, burnState?, caTarget?, durationOverride?, dvOverride?}`. `mode:'solved'`+target = ΔV magnitude ONLY from `progNmComputeEdgeDv`/`dvOverride` (components are display mirrors refreshed each recompute); `mode:'manual'` = ΔV = |vector|. Legacy `type:'MANEUVER'` entries in old saves still replay through a shim and migrate LAZILY on touch (never eagerly on load — old files must round-trip byte-identical until the user touches an event). The shared predicates `_evIsSolvedManeuver`/`_evManeuverTarget`/`_evIsManualBurn` (570 top) are the ONLY sanctioned way to branch on maneuver-ness — grep for any literal `=== 'MANEUVER'` you're tempted to add and use the predicate instead.
- **Physics results live in module side-tables keyed by missionId** (`_physTrajByMission` in 565), NEVER on `m` — anything on `m` leaks into autosave. Transient display fields on log events use the `_underscore` convention (`_expanded`, `_settles`) — check how autosave strips/ignores them before adding more.
- **One body-position source**: `progBodyEphemState`/`physBodyStateAt`/`progBodyWorldPos` (real JPL mean elements evaluated at `PROG_ACTIVE_PROGRAM.epochJD` + MET). `progBodyWorldPosCalibrated` is a thin legacy alias. If renderer and physics ever use different position paths, trajectories visually detach from planets.
- **ALL propagation through `physPropagateSegment`** — no ad-hoc integrators anywhere.
- **Duration precedence**: `durationOverride > physics leg TOF > launchWindow > Hohmann` (MATH.md §7e).
- **Two-layer rendering** (574): world SVG carries GEOMETRY ONLY in render units (km × zoom; zoom = `_TRAJ_VB`/cam.wKm; constant ±200-unit horizontal viewBox — big raw-km coordinates BREAK software rasterizers, which is why `viewClampUnits` exists); the overlay SVG carries ALL px-native symbology (labels, markers, ticks, gizmo) via `_trajRegisterLabel`/`_trajResolveLabels`/`_trajWorldToScreen`. ONE projection seam: `_trajProjectVec(x,y,z,az,el)`. Painter depth-sorting via {depth, svg} records.
- **Solved legs record `burnState`** (the exact pre-burn departure state) and mid-leg-authored MNODEs carry `e.burnState`+`e.burnFrame` — `physLegStateAt` re-propagates from the leg's recorded `initState`/ctx so hover rails, gizmo spawns, and replay can never disagree. Keep this one-source-of-truth property.
- **Theming**: NO chromatic literals in chrome — only `var(--…)` seeds (set by `applyTheme`, 190) or the derived `--accent-tint-*` scale (styles.css `:root` color-mix). Data palettes are exempt and centralized: `PROG_BODY_COLORS` (570), `PROG_GEO_STYLE` (236), `VP_COLORS`/`TS_SERIES_COLORS`, neutral black/white alpha scrims.
- **Stage identity dual-use**: `stageDefinitionId` = human-readable NAME for LV stages, UUID for SC stages. Builtin presets resolve stages BY NAME against STAGE_LIBRARY — a mismatch silently creates a zero-mass ghost stage (the gate now guards this, but be careful renaming anything in `050-builtin-presets.js`).
- **S1.5 (stage-and-a-half) must be BECO-split before `lvPerformance`/`lvMaxPayload`** — splitters: `calculateWithS15` (150), `_fleetExpandStages` (560), `_tsExpandStages` (165). Any NEW consumer of vehicle stage data must expand first. This bug shipped twice.
- **Navigation**: `showPage(id)` only; modals via `openModal()`/`closeModal()`. `showPage('results')` is intentionally aliased to the orbits page inside `showPage()`.
- Escape user-provided names when interpolating into HTML (`_tsEsc`, `_mrEsc`).
- **`MATH.md` documents every physics model and is on the critical path** — any change to math (which a refactor should NOT make) requires updating it in the same commit. `PHYSICS_PLAN.md` is the historical record of how everything was built — treat as append-only history, useful for archaeology.

## 4. Suggested refactor scope (in priority order — but propose your plan in REFACTOR_LOG.md before starting)

1. **Split `570-mission-manager.js` (~3,000 lines)** into coherent modules: event model + predicates + migration; recompute/replay; event cards/inline editing; node-map rendering; band view; budget/state panel. Numbered files sort = load order, so new modules slot in as `5701-`, `5702-`… or renumber cleanly (renumbering has precedent: 065, 221).
2. **Split `574-trajectory-view.js` (~3,000 lines)**: camera/projection; world-layer render passes (rings/legs/bodies/surfaces); overlay/label system; event nodes/ticks/scrubber; LOD constants in one place.
3. **`5745-maneuver-gizmo.js`**: separate pure math (axes, decomposition, rails, pull-rate) from DOM plumbing; the hover/menu subsystem is shared by rings and legs and could be its own module.
4. **Naming seams**: three prefixes coexist (`prog*` = original program engine, `phys*` = physics engine, `_traj*` = trajectory view). A rename pass is HIGH RISK (this is a no-build-tool concatenated global namespace — a missed call site is a runtime error in some untested path). If you attempt it: one prefix family per commit, grep-verify zero stragglers (`lv_calc.html` after build is the ground truth to grep), full browser flow test after each.
5. **Dead code**: candidates accumulate around retired features (planet-phase calibration is retired — `progBodyWorldPosCalibrated` alias + `overrides` params thread through many signatures doing nothing; the plain-disc LOD tier is gone; `_trajGizmoClampCross`/`_trajGizmoDragComponentValue` are gate-pinned but off the live path). Removing gate-pinned dead code = remove the code AND its assertions in the same commit, and say so in the log.
6. **What NOT to do**: no build-system change (no bundler/minifier/modules — `build.py` concatenation IS the architecture); no TypeScript; no framework; no renaming of persisted field names (autosave/.program/session compatibility); no "cleanup" of the lazy-migration shim or legacy MANEUVER replay case.

## 5. Known traps (each of these has bitten a model before)

- Editing `lv_calc.html` instead of `src/` (it "works" until the next build silently reverts it).
- ASCII round-tripping that destroys `°`, `Δ`, `·`, `→`, box-drawing chars (gate catches via U+FFFD, but only after damage).
- `physKeplerPropagate` returns null on non-convergence — every caller handles it; keep that when moving code.
- Module-level `let`/`const` do NOT attach to `window` — in-browser debugging must eval in page scope, and cross-module references rely on plain concatenation scope. Moving a declaration between files changes nothing semantically, but load ORDER matters: a module can only reference earlier modules' names at module-level execution time (function bodies can forward-reference).
- The browser preview: config "lv-calc" serves the repo on port 7823. Dismiss the autosave banner first (`document.querySelectorAll('button')` → click text match /discard/i). `PROG_ACTIVE_PROGRAM` may be null on a fresh profile — `progMakeProgram('T')` first. `devSeedApolloMission({force:true})` (573) builds the standard test mission. Verification flows below.
- Two dismiss systems exist (gizmo click-away, placement-menu click-away) that compose via capture-phase ordering — test both after touching either.
- `git commit -m` with here-strings can fail on Windows ("unknown switch") — write a message file and `git commit -F`. The "geometric-repack failed / File exists" error after commits is benign.

## 7. CHANGE LOG PROTOCOL (mandatory)

Maintain **`REFACTOR_LOG.md`** at repo root, append-only, one entry per commit, written BEFORE you commit. This file is how the previous model (and the user) audit your work — write it for a reviewer who knows the old structure but hasn't seen your changes. Format:

```markdown
## [seq] <commit-ish subject> — YYYY-MM-DD
**Intent**: one sentence — what this change accomplishes and why it's safe.
**Type**: move | split | rename | dedupe | delete | mechanical-rewrite | OTHER (explain)
**Files**: old → new mapping for every moved/split/renamed thing (function-level granularity for splits: "missionRecompute → 5702-mission-replay.js").
**Behavior delta**: "none" (the norm) — or the exact observable difference and why it's intended.
**Deleted**: anything removed, with the evidence it was dead (grep counts, gate assertions removed alongside).
**Verified**: gate count + which §6 flows you actually ran (be honest — "gate only" is a valid entry for a pure move, but say it).
**Risk notes**: anything a reviewer should double-check.
```

Also maintain a running **`REFACTOR_LOG.md` header table**: module map delta (old file → new files), so the whole restructure is readable at a glance without diffing.
